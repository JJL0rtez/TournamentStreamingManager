# Operator Architecture v18

Cumulative patch through v17. Extract into the project root and restart the server. No data folder is included.

## Operator changes
- Acknowledged notifications retain their marks during incomplete initial node data and disconnection; only a complete online snapshot clears resolved marks. History loads persisted records before writing or reconciling them. Acknowledgements remain browser-local.
- The four live tournament action buttons share equal columns on desktop, with a responsive two-column fallback on small screens.
- The billboard position example and schedule editor use neutral charcoal/grey styling. The old billboard UI is removed; `/presentation?mode=billboard` and `/presentation?mode=schedule` both open the consolidated schedule/announcement/sponsor editor. Existing legacy data and server APIs are retained, but old billboard-specific layouts/presets are not implicitly copied into the active schedule document.
- Select an MP4 or WebM file, maximum 200 MiB, in the sponsor slide or camera rotation editor. The node saves it under `data/sponsor-media` with a generated name. Choose Save/Publish after upload to associate the URL with a display. A direct HTTPS media URL is still supported. Uploads are limited to one at a time and check content type, byte count and file header; this is not a full video decode check. Remote password-protected editing uses the normal operator unlock. Uploaded videos are muted in automatic playback for browser autoplay compatibility. Include `data/sponsor-media` in event backups. Removing a slide does not delete an uploaded file, since multiple displays may reference it.

## Architecture
- App.tsx now approximately 2,100 lines instead of 8,000+. Shared types and reporting, incident, readiness, hardware, quality, reliability and capture health features are separate modules. Each remains in the dashboard source directory. The remaining main camera/session controller is intentionally kept together to preserve lifecycle interlocks.
- Periodic API reads share a sequential, visibility-aware polling scheduler. Identical GETs are coalesced by the existing request client, hidden tabs reduce polling, and unmount cancels future polls. Media frame refreshes and clocks retain separate timers. No mutation commands are automatically replayed.
- Distributed dynamic recording is an opt-in extension of the v17 switchable disk sink. Ring leases and capture/relay membership remain intact while changing recording output. Output changes serialize with start, stop and recovery, and ambiguous outcomes fence the ring. Longer DirectShow IDs are accepted as camera member identities; human-readable ring labels with spaces are mapped consistently to valid wire IDs. Continue using the same software release on all nodes and coordinator. Do not change versions during live ownership.
- Standalone enable: `TOURNAMENT_DYNAMIC_RECORDING=1` on the capture service. Distributed enable: also `TSM_DISTRIBUTED_CAPTURE=1` and `TSM_DISTRIBUTED_DYNAMIC_RECORDING=1`, with the existing coordinator config and explicit remote-control opt-in if controlling another node. Keep both dynamic flags disabled until physical validation. The previously deployed pipeline remains the default. No claim of physical or live multi-node verification.
